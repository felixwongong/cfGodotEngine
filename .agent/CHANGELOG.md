2026-10-13 — `cfGodotEngine.Binding`: added a generic UI→source **event channel** (CatSweeper run `mark-mode` vs-4; purely additive). New source-owned `BindableEvent` / `BindableEvent<T>` (`binding/BindableEvent.cs`) are the event twins of `Bindable<T>` built on `Relay`/`Relay<T>` — deliberately **not** `IBindableBase`, so events are verbs and can never enter a `PropertyMap`/binding-key list; the object-channel erasure point `internal IBindableEventUntyped` mirrors the `IBindableUntyped` single-point doctrine. New `IEventSource` (`GetEventKeys()` + `IEventMap GetEvents`) and `IEventMap` (`bool TryEmit(string, object)` + `Keys`) with the hand-authored `EventMap`/`EventMapBuilder` (`binding/EventMap.cs`, mirroring `PropertyMap.cs`'s two-type layout; fail-fast on null/duplicate keys — stronger than `PropertyMap`'s silent last-wins). New `EventBinding : BindingBase` (`binding/EventBinding.cs`) connects the **parent** control's signal (default `pressed`, no NodePath) and emits the keyed source event with an exported `Variant` argument; it is **not** `[Tool]` and early-outs under `Engine.IsEditorHint()`, so an editor press never mutates game state, and it disconnects deterministically in `_ExitTree`. Payload policy: `object` on the map channel, exact-`T` fast path, `null` only for null-representable `T`, else a narrow `Convert.ChangeType` fallback (a scene-serialized Variant int arrives as a boxed `long`). `UIComponent` gains additive `IEventSource` forwarding (`GetEventKeys()` / `GetEvents`, editor-hint-guarded like `GetBindings`); `BindingKeyDrawer`'s `GetKeys()` gains an `EventBinding` branch inside the existing whole-file `#if TOOLS`. No change to `IBindingSource`/`IPropertyMap`/`Bindable*`/`BindingBase`/`Binding`/`CollectionBinding`/`KeyedCollectionBinding`/`StaticBindingSource`/`PropertyMap` signatures or behaviour, and **no generator change** (event maps are hand-authored; generator support is future work), so downstream games compile and behave identically unless they opt in. Tests: `Tests/CatSweeper.Tests/Binding/BindableEventTests.cs` + `EventMapTests.cs` pin subscribe/emit/unsubscribe, payload identity, the coercion ladder, payloadless events, handler-exception propagation, fail-fast builder errors, and map key/emit semantics using plain objects. **Not verified here:** real Godot signal delivery through a scene tree (this is a zero-consumer slice; NUnit cannot construct nodes and headless delivers no GUI input) is an open hold carried to CatSweeper run `mark-mode` vs-5 (StageUI wiring).

2026-10-13 — `cfGodotEngine.Debug`: debug UI is now touch-scaled and phone-fullscreen (CatSweeper run `debug-ui-mobile`). New always-compiled `DebugUiScale` (`debug/DebugUiScale.cs`, namespace `cfGodotEngine.Debug`) is the single density knob for the four code-built debug surfaces (`DebugWindowHost`, `InfoDebugWindow`, `CommandExplorerWindow`, `CommandConsoleOverlay`): `Factor` is 1 on desktop / 2 on touch-phone, `S(int)`/`S(float)` scale a base constant exactly once at consumption (base constants unchanged), and pure `GetFactorFor(mode, touch)`/`IsPhoneFor(mode, touch, width, height)` back the main-thread `Factor`/`IsPhoneMode`; the mode comes from the `debug/ui_scale_mode` setting (`auto`|`desktop`|`mobile`), re-resolved per read (no cached native result), registered with `ProjectSettings.SetSetting` only when absent and never saved, falling back to `auto` for missing/invalid values; `auto` classifies a phone only when touch is available **and** the shorter physical screen edge is ≤1200 px (rotation-insensitive, nonpositive dims never phone), so a touch tablet scales ×2 but keeps floating windows. The sweep doubles fonts (28→56, including inherited/theme-derived values via `ScaleInheritedFont`/`ScaleInheritedConstant`), StyleBox content margins, container separations, cell width (240→480), action minima (48→96), the host close target (120×120 at ×2) and the console button (120×144, its initial coordinate clamped inside the viewport only at ×2), and the responsive breakpoint (1000→2000), while ratios (0.92/0.65, 0.55/0.45), layer ids, the 500-row cap and anchors stay unscaled. `DebugWindowHost` additionally places cards on the safe viewport rectangle on phone-class screens — no cascade, no drag, only the top card visible with lower cards kept attached and state-retained so closing reveals the previous one — mapping `DisplayServer.GetDisplaySafeArea()` display→host by inverting the card's screen transform (`internal static MapDisplaySafeAreaToHost` with an internal `SafeAreaReader` test seam; no new public API or namespace), intersecting with the visible rect and falling back to the full rect for empty/nonpositive insets, nonfinite or singular transforms, empty intersections and headless/unembedded viewports; desktop and tablets keep the floating path byte-identical (pre-change captures at 1080×2560 and 1920×1920 reproduce exactly). A new whole-file `#if TOOLS` probe (`debug/Editor/DebugUiScaleProbe.cs` + `bin/debug_ui_scale_probe.tscn`) drives the real host/registry and the real builders on a controlled SubViewport, asserts attachment and liveness (not just rectangles) plus stack/console/width/resize scenarios, writes deterministic JSON under `user://debug-ui-mobile/`, exits nonzero on failure (including a `--force-fail` case) and releases every fixture reference so teardown stays free of leak/crash markers. Known limits: at 1080×2560 the ×2 info content (1055 px intrinsic) still overflows the 1032 px full-screen content width, so horizontal scrolling remains required (roughly 2 of 4 columns visible); real notch/cutout protection, touch-keyboard behaviour, tap routing and on-device rotation remain unverified human holds.

2026-10-11 — `cfGodotEngine.UI`: fixed hidden `UIPanel` screens still rendering (registry defect `ui-panel-canvaslayer-leak`). A panel's content sits under a child `CanvasLayer` (`Layer`), which is a `Node` rather than a `CanvasItem`, so `Control.Hide()` only flipped the panel root's `visible` and the canvas kept drawing (World UI over Stage UI). `UIPanel` now overrides `_Notification(NotificationVisibilityChanged)` and synchronizes every panel-owned descendant `CanvasLayer` from the panel's **effective** visibility (own `CanvasItem.Visible` plus every ancestor `CanvasItem.Visible` up to the tree root, since a `CanvasLayer` boundary severs native `is_visible_in_tree()` propagation). The gate is recomputed each sync from panel/ancestor state (never from a layer's previously forced value, so `Hide()` cannot latch); traversal is recursive and includes internal children, covering sibling/nested layers, delegating nested `UIPanel`s with the enclosing gate so a nested hidden panel stays hidden; `Control.Visible` flags, binding sources, and the `_Ready`/`_runtimeSourcePath` wiring are untouched. Lifecycle syncs on `_EnterTree`/`_Ready`, subscribes to ancestor `VisibilityChanged` and `SceneTree.NodeAdded`/`TreeChanged` while in-tree (dynamically added layers and reparenting reconcile before the next render), guards reentrancy with a private flag, and unsubscribes ancestor/tree signals in `_ExitTree` with no per-frame scanning, worker dispatch, or new service. `UIComponent.cs`, `UIRoot`, and prefab scenes are unchanged; the repair compiles into Release.

2026-10-11 — `cfGodotEngine.SceneManagement`: fixed async scene attachment to run on the Godot main thread (`GodotSceneManager.LoadSceneAsync`). The method now captures `TaskScheduler.FromCurrentSynchronizationContext()` at entry (after a main-thread guard) and passes it to **both** attachment continuations — the cached-task branch and the cold `ResourceLoader.LoadThreadedRequest` branch — so `ShowScene`/`AddChild`/`SceneTree.CurrentScene` assignment no longer run on a worker thread (previously the plain `ContinueWith` continuation was scheduled on the thread that completed the `PackedScene` load, producing `Changing scene can only be done from the main thread` / `Adding children ... only allowed from the main thread` errors, a null `SceneTree.CurrentScene`, and an orphaned controller). Added private `EnsureSceneMainThread()` (compares `Godot.OS.GetThreadCallerId()` with `GetMainThreadId()`), called at the top of `LoadScene`, `LoadSceneAsync`, `UnloadCurrent`, and `ShowScene`; a wrong-thread caller is rejected with `InvalidOperationException` before any cache/accounting or tree access, and a missing synchronization context is likewise rejected rather than falling back to a worker. Cache/preload accounting, progress reporting, cached fault/null behavior, Single eviction, and Additive attachment semantics are unchanged; `ISceneManager<TScene>` XML docs now state the main-thread entry requirement, the entry-time context capture, attachment-before-task-success, and the synchronous wrong-thread/invalid-entry exceptions. Bounded runtime proof (native World→stage→World, cold + cached, win/loss) accompanies this change; the full release R1–R10 matrix and export/package verification remain the VS5 scope.

2026-10-11 — `cfGodotEngine.SceneManagement`: added `ISceneManager<TScene>.UnloadCurrent()` and its `GodotSceneManager` implementation. `UnloadCurrent()` synchronously detaches the current Single-mode scene, clears `SceneTree.CurrentScene` and tracked-scene bookkeeping, and queues the node for deferred `QueueFree` — a null-safe no-op with no current scene, never double-freeing on repeated calls, and never bulk-clearing persistent root children (`UIRoot`, registered services). Single-mode `ShowScene` now delegates eviction to `UnloadCurrent()` and assigns the newly attached scene as `SceneTree.CurrentScene`; Additive loading is unchanged. Unload does not cancel, clear, or await outstanding `LoadSceneAsync`/preload work, and untracked additive scenes remain unowned (`activeSceneSet` is not populated). Main-thread only; destruction is deferred, so return means detached, not destroyed.
